AI 转换流水线

LangGraph 驱动的三阶段流水线，从全局分析到逐章转换再到全局组装，全程可观测、可重试。

输入
小说章节
→
Stage 0
Story Bible
质量门 →
Stage 1
逐章转换
→
Stage 2
全局组装
质量门 →
输出
专业剧本
Stage 0

全局分析

将整部小说送入 LLM，生成 Story Bible：角色网络、时间线、主题、伏笔追踪、地点索引。

  • 识别所有有名字的角色并分级
  • 梳理时间线（闪回/闪前标记）
  • 提炼 1-3 个核心主题
  • 追踪伏笔 setup/payoff
Stage 1

逐章转换

每章独立调用 LLM，传入 Story Bible + 前一章剧本作为上下文，并行生成场景。

  • 基于地点变化划分场景边界
  • 每个 block 标注 source_ref
  • 强制覆盖所有关键情节
  • Pydantic 逐场景校验
Stage 2

全局组装

按章节顺序拼接场景，重编号，运行语义校验器，生成最终剧本。

  • 连续 scene_number 分配
  • 7 项语义质量校验
  • 章节覆盖检查（防丢失）
  • 全局 annotation 生成

语义校验器

7 项自动质量检查，确保输出剧本符合行业标准和叙事逻辑。

结构性校验

ERROR角色一致性script 中使用的 char_id 必须在角色名册中存在
ERRORSlug 格式location_type / location_name / time 必须符合枚举
ERROR场景编号连续scene_number 必须从 1 开始连续递增
ERROR章节覆盖每个输入章节必须在剧本中有对应场景

叙事性校验

WARNING对白/动作交替同一 scene 中不允许连续两个同类型 block
WARNING时间线连贯相邻 scene 不合理的时间跳跃需标记
WARNING主角出场率protagonist 必须出现在 ≥ 20% 场景中
INFOSource Ref 覆盖每个 block 应标注 source_ref 追溯原文

快速开始

5 分钟内启动完整开发环境。

1. 启动 PostgreSQL

# 开发环境使用 Docker
docker compose up -d

# 默认端口 5432，数据库 scriptforge

2. 启动后端

cd backend
cp .env.example .env
# 编辑 .env 填入 LLM API Key
uv sync
source .venv/bin/activate
uv run uvicorn app.main:app --reload

3. 启动前端

cd frontend
npm install
npm run dev

4. 运行测试

# 后端测试
cd backend && uv run pytest

# 前端 E2E 测试
cd frontend && npx playwright test
开发服务器
前端 http://localhost:5173 | 后端 http://localhost:8000
